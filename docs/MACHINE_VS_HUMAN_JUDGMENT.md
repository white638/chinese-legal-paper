# Deterministic and Interpretive Research Checks

## 核心原则

Avereth 不再按“机器执行、人工签字”划分研究权限。模型可以承担研究者角色；系统关心的是
结论是否有可追踪证据、运行是否彼此独立、指标语义是否准确，以及推断是否超过设计能力。

研究检查分为两类：

| 检查类型 | 典型任务 | 合格证据 |
|---|---|---|
| 确定性检查 | 文件、路径、SHA-256、schema、集合重叠、指标复算、时间顺序 | 可重复执行的 validator 结果 |
| 解释性检查 | 构念边界、误判代价、竞争解释、证据诊断力、语境与理论意义 | 逐项理由、来源定位、替代解释和处置记录 |

解释性检查可以由模型研究者完成，但不能退化为一句“已复核”。它必须绑定具体材料、编码手册
版本、证据定位和可审计的研究运行。

## 研究运行与独立性

每次承重运行登记：

- `run_id` 与独立 `context_id`；
- 模型名称、修订版本与完成时间；
- system/user prompt 的 SHA-256、关键参数、输出 schema 与重试规则；
- 原始输出 Artifact ID、内容哈希以及输入材料版本。

系统不要求研究运行声明某种人类身份，也不要求 `identity_type` 或自我免责声明。真正的硬门是
来源和运行独立性：主运行不能同时充当自己的参照或裁决运行，不能复用同一上下文、输出工件
或内容哈希。

## 参照、稳定性与准确率

不同证据支持不同指标语义：

- 独立模型参照只能报告 `reference_agreement`；
- 同模型重复运行只能报告 `stability`；
- 只有外部基准才能报告 `external_accuracy`；
- confusion matrix、逐类 precision/recall/F1 仍须从逐项预测复算，并明确它们相对于哪套参照。

参照必须在主评估前冻结，覆盖完整测试清单，并包含逐项来源定位、理由、置信度、分歧状态和
处置结果。空参照、空预测、重复或缺失 ID、未解决分歧以及自我验证一律失败关闭。

## 解释性检查的执行

模型研究者在下列问题上给出有证据的判断：

- 构念是否抓住理论上关心的现象及边界案例；
- 案例和材料边界是否服务于研究问题；
- 竞争解释是否以最强版本呈现；
- 某类误差是否会改变本研究的实质结论；
- 公开记录沉默、法律功能等价或制度执行差距应如何解释；
- 诊断失败后应收窄到什么 Claim。

涉及受试者、知情同意、机构伦理、作者责任或用户对研究问题的显式确认时，仍执行相应治理
规则；这些规则不是文本编码或模型验证的人工金标准。

## 冲突处理

1. 确定性检查发现工件、哈希、集合或指标不一致时，结果为 `FAIL`；只能修复工件、登记偏离
   或修改设计后重验。
2. 解释性证据不足时，使用 `needs-independent-review`，由隔离上下文的研究运行补齐证据与
   处置，不因字段齐全自动 `PASS`。
3. 核心规则不适合项目时，应修改核心合同并增加回归 fixture，不在单篇论文或自由文本备注中
   创建例外控制面。
4. 收窄 Claim 时保留原诊断、失败结果和决定理由，使研究判断可复核、可回滚。
