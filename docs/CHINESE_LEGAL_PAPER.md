# 中文法学论文 Skill 1.0.0

`chinese-legal-paper` 是 paper1 / Avereth 的法学扩展。它提供自然语言入口、可执行核验和检索客户端，复用 `cnki-paper` 的来源、设计、执行、写作、评审与交付流程。普通论文工作区没有启用法律配置时，继续走原有流程。

## 直接使用

安装完成后，新开 Codex 会话，输入：

```text
使用 $chinese-legal-paper 帮我研究中文法学论文。
研究方向是【你的方向】，当前已有材料是【你的材料】。
先判断具体问题、最接近的研究和材料是否足够，再给出可行的研究方案。
```

已有稿件可以直接指定任务：

```text
使用 $chinese-legal-paper 审核这篇论文的法条版本、案例身份和引注。
逐项区分原文已核实、仅有题录、支持关系不足以及需要补材料的项目。
```

```text
使用 $chinese-legal-paper 修改这篇论文的论证与表达。
保留已经确认的研究问题和范围；先处理概念、法律主体、适用条件和反对意见。
```

用户可以要求选题、文献研究、研究设计、全文写作、修订、引注审计或投稿适配。局部文字修改按任务直接完成；正式研究沿用已有工作区，从最早缺口继续。技能不会因为用户只要求引注审计而自动改写整篇论文。

## 已实现的功能

| 能力 | 本版行为 |
|---|---|
| 唯一控制器 | 法律检查进入原 `status`、`plan`、`gate` 和收据绑定；没有第二套来源库、主张库或完成状态 |
| 法源与时间 | 登记法域、资料性质、发布主体、版本、适用时间及核验依据；现行法与历史法分开使用 |
| 裁判材料 | 区分真实裁判文本、编辑要旨、法院和程序信息；规则要求分别识别事实、诉辩观点与裁判理由 |
| 法学方法 | 规范解释、裁判分析、规范理论、比较法、实证法学、立法与制度设计、法律史七类方法卡，绑定既有研究设计 |
| 原文与引注 | 校验实际文本、文本区间、印刷页/PDF 页/条款/段号等定位；摘要不能冒充全文；转引登记实际读过的中介资料 |
| 变更失效 | 来源、主张、稿件或核验依据变化后，旧绑定和相应复核不能继续视作有效 |
| 写作与修订 | 继承 ProsePacket、protected atoms、语义保真和评审流程，补充主体、权利义务、条件、例外、救济与否定词检查 |
| 数据库接入 | 实现北大法宝 MCP 客户端以及 Crossref、OpenAlex、Semantic Scholar、Unpaywall 客户端；复用 paper1 的 Exa 与 CNKI 工作流 |
| 脚注 | 生成基础工作稿脚注，核查 DOCX 原生脚注引用和定义；复杂排版与视觉审查沿用 paper1 |
| 故障与费用 | 鉴权失败、限流、非法响应、权限缺失分别报告；北大法宝调用按次数及账户价格估算额预留并记账，不自动重试付费调用 |

这里的“实现”指规则、合同、检查或客户端已交付。方法卡不等于自动证明法律解释正确，结构检查也不代替实际阅读全文和实质评审。

## 资料从哪里来

| 渠道 | 配置 | 实际边界 |
|---|---|---|
| Exa | 当前环境已有 Exa 插件或 MCP | 优先用于公开发现；结果是候选，不能直接充当已核验全文 |
| CNKI | 已授权浏览器、用户真实登录及机构/个人权限 | 分别确认题录、在线正文和下载权；复用原有搜索、详情、导出、下载等技能，没有新增“免授权全文接口” |
| 北大法宝 | 安全环境变量 `PKULAW_MCP_TOKEN`，以及实际订阅、调用/金额上限 | 从真实 `tools/list` 发现工具与参数；客户端只支持已实现的官方网关和协议形式 |
| Crossref | 可选 `CROSSREF_MAILTO` | DOI 和题录检索；本版保留相关性排序，在前 1000 项内有限翻页 |
| OpenAlex | `OPENALEX_API_KEY` | 元数据及开放获取线索；当前账户配额、收费按官方实时规则执行 |
| Semantic Scholar | 可选 `SEMANTIC_SCHOLAR_API_KEY` | 题录、摘要和可用 OA 链接；匿名请求可能限流 |
| Unpaywall | `UNPAYWALL_EMAIL` 和已知 DOI | 查合法开放获取位置，不自动下载全文 |

凭据通过用户自己的安全设置提供，不能写进论文、仓库、参数文件或聊天示例。`doctor` 只报告凭据是否存在；存在不代表有效，工具已实现不代表已取得订阅。

北大法宝接口依据[官方接入资料](https://mcp.pkulaw.com/)及[账户与价格页面](https://mcp.pkulaw.com/pricing)。客户端预算按调用者核实的单次价格估算，不能约束供应商最终扣费。无法确认费用时不执行收费调用。权限不足时继续不依赖该资料的工作，并保留相应主张缺口。

## 工作区与检查结果

先按 `cnki-paper` 建立或继续真实工作区，再由本技能启用 `legal_profile=chinese-law-v1`。以下路径相对已安装的 `chinese-legal-paper` 目录；运行需要 Python 3.10+。

```text
python -X utf8 scripts/legal_paper.py doctor
python -X utf8 scripts/legal_paper.py enable WORKSPACE
python -X utf8 scripts/legal_paper.py enable WORKSPACE --apply
python -X utf8 scripts/legal_paper.py check WORKSPACE --stage audit
python -X utf8 ../cnki-paper/scripts/avereth.py --skills-dir .. status WORKSPACE --json
python -X utf8 ../cnki-paper/scripts/avereth.py --skills-dir .. plan WORKSPACE --json
```

不带 `--apply` 的 `enable` 只预览；应用时保存原配置备份。它不会创建伪来源、伪分析或完成凭证。新建空的法律来源扩展仍需要真实材料和核验。

| 新增工件 | 作用 |
|---|---|
| `reference_materials/legal_sources.json` | 扩展唯一来源登记中的 Source ID，绑定法域、原文访问、法源版本、程序与身份复核 |
| `legal_analysis.json` | 扩展已有研究设计中的 Claim ID，登记方法、法律适用范围和理由 |
| `legal_citations.json` | 绑定当前规范稿、实际文本区间、定位与引用支持关系 |
| `legal_review.json` | 绑定当前稿件，记录来源、适用、支持、方法、反对意见、语义与规则复核 |

各阶段只要求当前任务适用的工件。纯引注审计不被强制补做整项研究设计；研究终点的任务也不会被误判成必须写完论文。

`PASS` 必须和 `through_stage` 一起阅读：只检查到 acquisition 的结果没有覆盖正文引注。`is_completion_receipt=false` 表示该报告不是论文完成收据。最终是否完成仍由原控制器及当前文件对应的收据决定。

## 引注和稿件交付的范围

自动引注覆盖检查以带 `[^CIT-...]` 标记的 UTF-8 Markdown 规范稿为入口。内置 `working-footnote-v1` 覆盖法规、案例和普通学术文献的基础工作稿脚注，不等于完整《法学引注手册》实现，不猜测卷期、页码或出版信息。

目标刊规则优先。用户提供实际规则后，可以绑定规则依据并按规则复核；本版没有自动生成任意期刊 CSL 样式、复杂短引和所有交叉引用。直接对复杂 Word/LaTeX 稿件的全面自动引注覆盖仍需扩展，当前使用 paper1 既有规范化流程和逐项核对。

原生 Word 脚注的结构检查与页面视觉检查是两件事。`audit-docx` 不证明版面美观、页码正确或法律论证成立。沿用的稿件管道可能需要 Node、Pandoc 或渲染器；按实际输出任务运行原有依赖检查，不能仅凭本技能的 `doctor` 宣布所有导出工具可用。

## 从源码安装与迁移

本技能必须和含法律桥接的 `cnki-paper` 一起安装。推荐使用本版本的完整源码包，在解压后的仓库目录执行原有可恢复安装器：

```text
python -X utf8 tools/install_runtime.py --host codex --json
python -X utf8 tools/install_runtime.py --host claude --json
```

只执行所需宿主那一行。先试装到独立目录可加 `--runtime-home ACTUAL_TEST_DIRECTORY`。安装器会构建对应宿主、备份替换文件，再检查 agent、入口、运行时一致性和控制器依赖。不要把 Codex 包直接装进 Claude 目录，也不要将未经构建的 `SKILL.source.md` 当作运行时入口。

分发的宿主运行时 ZIP 便于检查和受控部署；已有安装优先使用源码安装器，不直接覆盖整个技能目录，以保留备份和未受管的技能。本仓库保留原有第三方许可与声明；各组件继续适用其已有许可范围。
