# 引注、脚注与交付

先判断引用是否成立，再处理格式。身份正确、定位正确与足以支持当前结论分别核验；法条存在不代表适用于本案事实，真实案例也不代表普遍裁判规则。

## 1. 核查顺序

1. 回到原始发布机关、法院文书或正式学术出版记录，核对题名、主体、版本、案号、年份、DOI 等身份。法律数据库编辑的要旨须标记其性质。
2. 读取当前权限下实际取得的原文，保存必要的合法文件和具体位置。只有摘要时，只能说“摘要报告/提出……”，不为全文主张提供假页码。
3. 判断引用用于定义、事实、法律依据、学说立场、反例还是比较材料；检查推断是否超过原文和适用范围。把最有力的反对意见与回应落实到真实来源。
4. 检查现行/历史版本、事实时间、法院层级、裁判程序、不同法域和政策/法律形式，不把这些差异在格式化中抹去。
5. 检查转引链、译文与原文关系、删节及关键否定词。不能仅凭二手材料把原作者列为实际阅读来源。转引必须登记实际读过的中介文献，并在正文明确链条。

## 2. 格式优先级

以目标刊当前官方投稿规则及用户合法提供的规则版本为准，并保留原文依据。没有规则时用透明的工作稿格式，不擅称完整执行《法学引注手册》。本包没有复制未取得授权的手册全文。

内置 `working-footnote-v1` 只覆盖法规/政策、案例与普通学术文献的基础脚注。它不推断期号、卷号、文号、作者、出版者或页码，也不自动生成“同上注”等依赖顺序的简写。书章、特定外国判例体系和期刊特殊著录在已有写作/导出流程中据真实规则处理；`journal-supplied` 当前接受规则绑定并要求人工适配，不冒充自动 CSL 样式引擎。

```text
python -X utf8 scripts/legal_paper.py check WORKSPACE --stage build
python -X utf8 scripts/legal_paper.py render-notes WORKSPACE
python -X utf8 scripts/legal_paper.py audit-docx ACTUAL_OUTPUT.docx
```

`render-notes` 仅在法律 build 合同通过后，打印 Markdown 原生脚注定义。它不写回规范稿，不替换现有脚注。将定义并入稿件后，稿件哈希已改变，应重新绑定和检查，再交给 paper1 的现有 native DOCX/LaTeX 导出。对既有 Word 稿先使用原有稿件解析/规范化能力；不直接修改 OOXML 而绕过规范稿。`audit-docx` 只检查原生脚注引用与定义对应、重复定义、空脚注集合和残留 Markdown 标记；不证明页码准确、Word 排版正常或所有正文都有正确引用。

当前脚本以带 `CIT` 标记的 UTF-8 Markdown 稿作为自动引注覆盖与工作脚注格式化入口。直接对 LaTeX、原始 Word 复杂交叉引用的全面自动覆盖尚未实现；先用现有 paper1 管道取得可绑定的规范文本并逐项登记，或在原有审计路径中人工核对。不得把仅 DOCX 结构检查的 PASS 宣布成法学引注全通过。

## 3. 法学语义复核

对比改写前后主体、权利/权力、义务、法律责任、授权条件、例外、证明责任、救济、否定、数量和时间。特别检查“可以/应当/不得”“成立/生效”“违法/无效”“参与/代表”“相关/导致”等变化。标题和提纲围绕具体法律争议及论证推进，不能因为整齐而强制对称分节，也不以禁词表或“去 AI”替代论证。

## 4. 完成条件

法律 review 对当前稿件记录来源、适用、支持关系、方法、反对意见、语义和引注规则的复核依据，阻断问题都有处置。之后仍须通过 paper1 原有独立评审、全文证据要求、原生脚注检查、渲染检查、匿名化与目标刊要求，并由当前 artifact 指纹对应的 audit/output 收据确认。截图、结果摘要、旧稿 PASS 或本技能的 PASS 都不能代替这些收据。
