# Research Design (jop-research-design)

JOP is **methodologically diverse** and demanding about each tradition. The design must credibly connect
the argument (`jop-theory-building`) to evidence — and, because **acceptance is contingent on
replicability**, it must be one a **JOP replication analyst** can re-run. This skill is mode-aware: pick
the section matching your work and defend it against the strongest alternative.

## When to trigger

- Specifying identification, case selection, or experimental design
- A reviewer questioned causal claims, case choice, external validity, or a confound
- Preparing a pre-analysis plan
- Justifying why your design adjudicates the rival account from `jop-literature-positioning`

## Quantitative / causal inference reporting
- Report the registered estimand, assumptions, diagnostic artifacts, and observed ceiling under
  `CORE.CAUSAL.ESTIMAND_BINDING` and `CORE.CAUSAL.ASSUMPTION_DIAGNOSTICS`.
- For staggered panel work, cite `CORE.PANEL.STAGGERED_DESIGN` and expose the registered cohorts,
  comparison group, timing diagnostics, implementation identity, and inference disposition.
- Report `CORE.INFERENCE.DEPENDENCE_ALIGNMENT`, `CORE.INFERENCE.MULTIPLICITY_PLAN`, and
  `CORE.INFERENCE.SENSITIVITY_BINDING` records where applicable. JOP does not select the procedure.

## Experiment reporting (lab / survey / field)
- Report the core-registered design, units, treatment, estimand, sampling/generalization ceiling,
  diagnostic Artifact IDs, deviations, and disposition. Missing records return to empirical-research.
- Put ethics/IRB and consent documentation in the locations required by JOP submission policy.

## Formal-empirical reporting
- State the core-registered target, model-to-evidence mapping, rival account, proof/diagnostic Artifact
  IDs, and observed ceiling. Explain those records without adding a venue-local test.

## Qualitative / case-based reporting
- Report the core-registered case-selection rationale, scope, competing explanation, process-tracing
  evidence matrix, Artifact IDs, and observed inference ceiling. Do not define venue-local tests.
- Put archive, interview, and fieldnote documentation where `jop-replication-and-data-policy` requires it.

## The adjudication test

Present the strongest rival and its core-registered adjudication record. If either is absent, return the
design to empirical-research; this overlay only determines placement and clarity.

## Design for replicability (JOP-specific)

- Report the registered estimator/software identity and reproduction command from core — the analyst
  re-runs that implementation; venue prose cannot replace it.
- Report the core registration/deviation record so readers can see whether the target moved.
- Keep the design within the **page budget**: defend it crisply in the main text, push diagnostics to
  the Online Appendix.

## Anti-patterns

- Hiding a failed panel/dependence diagnostic or silently changing the registered implementation
- "Causal" language on a design that only supports association
- Omitting the core case-selection or rival-adjudication record
- A design whose results cannot be regenerated by a clean script (fails the replication check)

## Identification objections and the JOP-credible answer

A JOP referee asks the same question of every empirical design: would the result survive if the cleanest
rival story were true? Match the objection to the design move that closes it; keep diagnostics in the
Online Appendix.

| Referee objection | The design answer |
|-------------------|-------------------|
| "Leans on selection-on-observables" | Report the core assumption/sensitivity disposition and bounded claim |
| "Timing diagnostic is unclear" | Cite the registered panel diagnostic artifact and consequence |
| "Exclusion restriction is doubtful" | Report the registered assumption defense, diagnostic status, and ceiling |
| "Case selection is convenience" | Show the core-registered selection rationale and scope; return an absent record to empirical-research |

## Worked micro-example (illustrative)

A hypothetical paper reports a staggered municipal-policy design. Its JOP account names the registered
`CORE.PANEL.STAGGERED_DESIGN` target, links the timing and sensitivity artifacts, and states whether core
retained, narrowed, or withdrew the causal interpretation. The venue example does not prescribe an
estimator or sensitivity formula.

## Referee pushback patterns and the JOP fix

- *"Your causal claim outruns the design."* Report the core inference disposition and return any proposed
  redesign to empirical-research; the response letter cannot create a new identification route.
- *"This is not reproducible."* Surface the core reproduction command, environment, and stochastic
  identities; return any implementation change to empirical-research.

## Output format

```
【Mode】quant-causal / experiment / formal-empirical / qualitative
【Core contract】id + revision + registered estimand/claim
【Core diagnostics】assumption/dependence/measurement Artifact IDs + disposition
【Rival adjudication】registered record + evidence locator
【Replicable?】fully scriptable for the JOP analyst? [Y/N]
【Next】jop-data-analysis
```
