# 选题阶段的经验—理论、归纳—演绎循环

选题不是先凭经验起题、再找理论包装，也不是先套理论、再挑支持材料。执行两个互相纠偏的推理通道：经验材料形成模式和异常，理论产生预期和反证条件；二者循环修订后才形成候选题。

## 先发散问题，再深核 finalist

本文件的完整归纳—演绎矩阵只约束 `finalist`，不得拿它作为生成每个原始想法的前置成本。
`direction_first` 先在 `avereth-topic-packet/v1` 的封闭输入范围内生成问题种子；此时不读取工作区数据、
代码本、旧题／旧稿、工作区文献、既有方法或材料便利性，也不先造标题。问题种子只需登记异常／未知、
为何重要、候选家族和什么观察会使其失去价值。

宽发散默认从适用的核心问题、竞争机制、边界比较、历史过程、概念测量、反常负例、跨层级和高风险理论
通道生成 12–18 个种子；聚类、合并与初筛后形成 6–9 个 `screened` 候选，覆盖至少四个适用家族。
方向较窄时可以更少，但须保存尝试家族、逐项淘汰／不适用理由和“新增只会成为陪跑项”的判断依据。
每个 screened 候选登记方向契合、生成通道、材料消融、工作区关系、七维语义签名与最近似候选差异；
组合审计通过后，用户选择 2–3 个进入 `finalist`，再执行本文件以下六渠道、循环、撞车与完整矩阵。

聚类、合并与淘汰不是候选自报：`research_decision.py host-screen` 的受控 receipt 必须给每个封存 seed 一个且仅一个
retain／merge／drop 去向，并绑定所有主清单 candidate core、问题家族和当前方向契约。方向契合分 topic、problem、
contribution、trajectory 四层，每层登记 verdict、契约字段 basis 与实质 rationale；任一层 weak／uncertain 即阻断。

工作区材料只在 seed seal 后进入，并逐项标为 `support`、`challenge`、`partial`、`incidental` 或 `lure`。
`direction_first` 主清单要求材料消融 `survives`；`depends` 单列为材料机会旁支；`fails/lure` 淘汰。
仅当材料揭示此前未见、但仍高度符合方向契约的真实异常，才可追加明确标源的 `material_discovery` 候选。
该追加必须来自受控 material-discovery receipt，绑定材料 path/SHA、相对封存 seed 与 screened core 的 previously-unseen
判断及四层 strong 契合；自报生成通道或材料关系不构成来源证明。用户若一开始明确选择 `workspace_extension`／
`material_opportunity`，则首轮生成改走 declared-material projection：仅声明文件的有界内容进入 prompt，receipt 绑定
投影与当前 path/SHA，并仍须生成、筛选多个实质问题家族。

## 六渠道输入及证据身份

入围候选的归纳与演绎在同一材料上交汇：把旧解释的预期与替代解释的预期并列，指出哪项观察
能区分两者，什么结果意味着不必改变原认识，以及什么结果足以要求修订。判别材料须能定位到
可取得的事件、过程、文本段落、比较或测量，不能只写“扩大样本”或“增加访谈”。在现有
`assumption_challenge` 中记录这些条件；来源身份和最终确认沿用 `topic-selection-protocol.md` §6。
独立复制可以检验可信度或范围，无须预设相反结果。

| 渠道 | 用途 | 证据身份 | 硬规则 |
|---|---|---|---|
| `practice-experience` 实践经验 | 从用户本轮材料、田野／工作遭遇或有位置说明的观察提出真实张力 | `user-provided` / `situated-context` | 登记题面、消息、访谈／田野编号或本地路径；实践负责提出问题，不自动成为已证事实 |
| `memory-experience` 记忆经验 | 生成现象、案例、政策后果和异常的候选线索 | `hypothesis-only` | 不能写成事实、不能充当引用；必须由网络、用户材料或活动发表轨道的学术来源追核 |
| `web-experience` 网络经验 | 获取当前政策、统计、事件、机构实践和公开材料 | `traceable-context` | 登记 URL、页面标题、机构、采集日期和材料类型；优先官方/原始来源；法律法规、规范性文件与司法案例优先用北大法宝（pkulaw.com）系统检索，法规记发文字号与时效性状态、案例记案号 |
| `memory-theory` 记忆理论 | 召回具名理论、概念、机制和经典命题 | `theory-candidate` | 理论名称、前提和命题都只是候选；须用活动发表轨道的学术文献或可靠原典复核 |
| `cnki-theory` 知网理论 | 核验理论定义、争论、机制、边界和中国语境修正 | `verified-literature` | 登记能解析到当前 literature registry 的 Source ID/稳定 CNKI URL、摘要/详情/全文等级和日期；题名命中、自造编号或普通网页不算核验 |
| `international-theory` 国际理论 | 核验国际理论定义、争论、机制、边界与最新对话 | `verified-literature` | 登记能解析到当前 literature registry 的 Source ID、DOI／出版社／合法 OA 原文、摘要/详情/全文等级和日期；发现页、片段、BibTeX 或未登记编号不算核验 |

用户提供的访谈、文本、数据或案例材料归入 `practice-experience` 并登记本轮来源或本地路径。六渠道不是固定配方：每个候选须有 practice/web 中至少一个可追溯经验锚点，并按 `publication_track` 使用经内容核验的理论锚点与撞车链——`cnki-cn` 要求 `cnki-theory` 与 CNKI 撞车，`international-ssci` 要求 `international-theory` 与国际发现／原文撞车，`mixed` 同时要求二者。两个 memory 渠道均可为零，不得为凑齐结构而制造模型记忆材料。

**既往稿件隔离（硬规则）**：用户本人的既往论文与手稿——包括本机其他论文工作区、会话记忆中的论文项目、未发表文稿——不进入六渠道输入的任何一类：不作为经验线索、理论候选、文献证据或选题锚点，也不得用来预设新论文的研究方向。它们未经同行评议、不具文献权威性；以旧稿定向还会固化选题、压缩新方向的创造空间。仅当用户在当前任务中明确要求延续、扩展或引用某篇既往稿件时才可纳入，且按未发表手稿处理：只能作为 `practice-experience` 登记本地路径，不得充当理论或文献支撑。

## 视角×追问循环（检索深化引擎）

关键词组保证检索广度，深度靠好问题：自动化研究的核心是自动提出好问题（借鉴 Stanford STORM/Co-STORM 的两项发现——视角引导提问、检索接地的模拟追问；方法论移植，不引其代码与检索器）。归纳通道第 2、5 步与演绎通道第 5 步的定向检索按本节执行。

**视角发现（3–5 个）**。从三处提炼，不凭空生造：① 范文与高被引文献的作者视角（Exemplar/SOTA 拆解已有：各自从什么关切进入主题——制度设计、行为激励、过程机制、比较差异、规范争论等）；② 文献中的争论方（对同一现象给出竞争解释或对立评价的立场各算一个视角）；③ 利益相关者视角（政策的设计者/执行者/对象，仅当材料可支撑时）。每个视角登记一行：视角名、关注什么、忽略什么；视角合起来应互补覆盖主题，单一视角不得垄断问题链。

**每视角问题链（3–5 问）**。以视角为立场连续提问：初始问题 → 活动发表轨道／网络定向检索 → 读摘要/详情/原文更新理解 → 基于新信息提出追问。每问登记问题、检索式、命中来源、答案要点、追问或"未答"。不建新工件：已答问题的来源与要点写入输入账本（WE/CT/IT 行，Trace 注 `视角Pn-问题Qm`）；**未答问题就是证据缺口**，汇入 `sota_gap_map.md`，在 citation 阶段派生检索组，并在动机选项的材料可行性栏如实标注。

**反收敛检查（moderator 机制）**。每轮结束扫一遍"检索命中但未被任何问题链使用"的旁支信息：其中是否藏着更好的问题、异常或负例？至少提出 1 个由未用信息触发的新问题再进下一轮；连续两轮提不出即停机。此检查与"只收集支持材料不算检验"同源，防止问题链只在初始预期附近打转。

**边界（不采纳的部分）**：STORM 的百科式综合文体不进入写作阶段——论文由确认贡献承重，不是话题信息的中立汇编，Contribution-First 优先；不搞全自动端到端，视角清单与未答问题随动机选项呈现给用户，用户可增删视角、改判方向（与 Co-STORM 人在环立场一致，与本套件用户硬门同构）；引用纪律仍按 citation bank 与页码分级执行，不采用其逐句挂引的百科规范。输入账本超过约 30 行时，可在矩阵开头加一个纯缩进列表的"概念层级速览"帮助导航，不另建导图工件。

## 归纳通道：经验 → 模式/异常 → 候选概念

1. 汇总经验线索，不区分是否“符合预期”；先标来源层和核验状态。用户既往稿件的主题、框架与结论不得混入线索池（见既往稿件隔离）。
2. 对可核验材料做开放比较：重复出现什么、何处发生变化、哪些案例反常、哪些分类失效。
3. 提炼候选模式、类型或机制线索，并写出至少一个负例或不符合模式的观察。
4. 公开先验视角：为什么观察这些对象、变量和材料，采用了什么分类，忽略了什么。不得声称“数据自己说话”。
5. 将归纳结果送入活动发表轨道的学术检索（按视角×追问循环执行）：检查该模式是否已有名称、机制是否撞车、异常是否已被解释；`mixed` 同时检查中文与国际对话。

归纳的产出不是终局理论，而是可被文献和新材料推翻的候选概念、模式或问题。

## 演绎通道：理论 → 命题/预期 → 经验检验

1. 可从 `memory-theory` 召回与问题真正相关的具名理论候选，也可直接由活动发表轨道中已核验的争论归纳理论；无论入口为何，都用 `cnki-theory`、`international-theory` 或二者（依 `publication_track`）核验定义、核心前提、既有命题和范围条件，不以记忆层数量或方法新旧代替相关性与覆盖。
2. 对每个候选理论写出前提，不把前提伪装成结论。例如“行动者追求某目标”本身必须接受事实检验。
3. 推导方向明确的命题、机制链或分类预期；写出若理论成立应该观察到什么。
4. 同时写出反证观察：出现什么材料时应拒绝、收缩或改写该理论解释。
5. 回到网络、用户和活动发表轨道的学术材料检查（定向补检按视角×追问循环执行）：理论能否解释已发现模式、异常与负例，是否需要加入边界条件或更换理论。

演绎的产出不是“套用某理论”，而是一组能被材料区分、支持或反驳的可观察预期。

## 循环与停机规则

按以下链条至少完成一轮：

`经验线索 → 归纳模式/异常 → 理论候选 → 演绎预期/反证 → 新一轮定向检索 → 修正模式、理论或边界 → 候选题`

- 经验只有堆积、无法形成比较或异常：重做分类与样本边界。
- 理论只能复述前提、无法产生独立可观察预期：淘汰该理论。
- 理论与经验完全吻合也要主动找负例；只有支持材料不算检验。
- 经验与理论冲突时优先保留冲突信息，形成理论边界、竞争解释或更有价值的研究问题。
- 任何方向未完成 `publication_track` 要求的真实内容核验和有日期撞车检查，不得作为最终推荐；理论与 Collision Trace 中的 Source/Query ID、DOI 或 URL 必须解析到当前注册表的对应来源或已完成查询。国际轨道的发现页或书目元数据不能替代 DOI／出版社／合法 OA 原文核验，CNKI 不适用也不能成为失败理由。

## 真空白、研究问题与比较设计

文献少只是一项检索现象，不等于知识空白。每个候选题都要依次排查四种可能：研究对象出现不久、正常发表时滞尚未结束；同一问题使用了不同术语或被相邻议题覆盖；已有研究存在但精确题名未命中；该对象本身缺乏足以支撑论文的理论张力或知识增量。排查后按 `research-gap-diagnosis.md` 写“两轴诊断”：只选一个主要落点——概念／测量、理论／解释、证据、识别／方法、范围／群体、行动／实践；再登记当前无法下结论是因为不足／不精确、覆盖偏倚、不一致／不可比还是错配／条件变化。“知识空白”是两轴组合后的总状态，不与六个落点并列。不得用“尚无以某组织为对象的论文”“仅检得若干篇”、七类标签齐全或方法更新直接代替贡献论证。

按 `research-question-design.md` 为每个候选方向写一个暂定研究问题，标一个主类型并显式展开 O-T-I-P-R。按答案任务而非疑问词分类：“如何演变”可能是描述性，“如何影响”是解释性，“如何改善”是操作性。解释性、预测性和“有些……有些……”式强关系问题先确定一个共同结果；描述性、操作性、规范性弱关系问题不得为迎合因果格式虚构结果变量，但仍要写清还原对象、主体—目标或行为—规范联系及设计依据。

若问题采用“有些……有些……”结构，就要说明这些单位为何可比、结果形式如何分类、比较提供什么反事实。核心案例可以占据主要篇幅并提供完整过程证据，其他案例只承担路径对照和反事实功能；这仍是一个关于制度形式选择的研究问题，不是“核心案例如何形成”与“其他路径为何不同”两个并列问题。只有当单个案例内部具有跨时段、子案例或可区分的过程观察，足以回答一个机制问题时，才采用纯单案例设计；不能因为对照材料难找而把比较问题改称单案例问题。

不同制度形式不自动构成发展阶段。除非材料证明它们属于同一过程且具有真实时间顺序，否则用“由既有机制承接”“以非正式平台协调”“创设条约型政府间组织”等并列结果，避免把“停留、跨越、落地”写成目的论序列。制度研究还要区分议程提出场域与组织的法律人格、授权或协作关系与法律隶属关系、成员资格开放与创设时实际参加；不同法律阶段或观察时点造成的差异不能伪装成需要解释的悖论。

完整矩阵只保留 2–3 个 finalist，或在有效窄方向豁免下保留唯一 finalist。它不对 seed/screened 设置完整字段配额。进入矩阵的 finalist 必须是检索后证据充分、彼此有实质差异且对用户决策有用的真实方向；合并同义项，剔除无证据或不可行项，不制造陪跑项。每个选项都要回链已登记 `PO-*` 并说明 `Problem Warrant`，引用输入账本中的可追溯经验 ID 与发表轨道要求的理论 ID，完成归纳和演绎；模型记忆 ID 可有可无。`Collision Trace` 必须按 `publication_track` 落到当前 literature registry 中可解析的真实 Source ID/Query ID/URL 和核验日期：中文轨道用 CNKI，国际轨道用国际发现链与 DOI／出版社／合法 OA 身份，混合轨道同时保留二者；只符合编号外形的 `S999`／`INTL-S999` 不算溯源。`Provisional Title` 只压缩当前问题，`Title Function / Claim Boundary` 只能是 `question-led` 或 `claim-neutral`，并明确不预断何种结果、机制、因果或概念；执行前不得标 `result-led`、`finding-led` 或 `claim-led`。`Provisional Research Question` 必须是可回答的问题而非题目；`Primary Question Type` 只标描述性、解释性、预测性、操作性、规范性之一；`O-T-I-P-R` 按 `O=…；T=…；I=…；P=…；R=强关系/弱关系：…` 填写；`Gap Reality Check` 在原列内登记 `Status=corroborated`、一个 `Primary Locus`、一个或多个 `Obstruction`、具体 `Gap Claim`、当前 `SYN-*` 依据、替代解释、研究责任与撤回条件，不新增七列；`Outcome Unit & Comparison Design` 对强关系问题写共同结果、分析单位和比较/反事实安排，对弱关系问题写还原对象、决策单位或规范判断对象及相应证据/推理设计。标题是否有洞见、gap 是否有学术分量由用户与证据化评审判断，门禁只检查功能、边界、结构和身份，不按长度、公式、标签或吸引力评分。

## 选题判决

有分支品味卡时，`taste_judgement.md` 的成对裁判排序、四味判定与平庸路径进入 C0 的 retain/merge/drop/defer 理由；它是与已发表研究比较得出的信号，不是放行门，采纳与否及理由须写明。优先选择同时满足以下条件的方向：源于可追溯 `PO-*` 而非现成工具；有可核验的经验抓手；归纳能形成非平凡模式或异常；理论能产生独立可观察预期；存在潜在反证；经验—理论之间有需要解释的张力；空白由当前 `SYN-*` 支持的具体未知、阻断原因和可撤回研究责任构成，而非对象稀缺；问题主类型与 O-T-I-P-R 清楚；关系强弱、结果/决策单位和设计逻辑匹配；材料可得；活动发表轨道的文献足以支撑但尚未把同一问题写尽。向用户展示选项时，明确哪些来自实践／网络、哪些仅是记忆假设、哪些已由 CNKI、DOI／出版社／合法 OA 原文或二者核验，以及理论、经验或 gap 在哪一步被修订。方法新颖、模型可跑或已有数据不得单独提高选题优先级。
