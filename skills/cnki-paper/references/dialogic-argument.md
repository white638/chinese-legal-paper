# 对话式研究与论证协议

本协议把论文视为一个可核验的学术回应：先准确交代已有声音，再说明作者接受、
反对、限定、重构或推进了什么，最后用已登记证据说明这种回应为何成立、谁会关心、
以及接受它会改变什么。

它贯穿 `acquisition → research → design → execution → build → audit`，但不改变
CNKI-Paper 的八阶段状态机。真实来源、目标刊规范、研究设计、证据力度与推断边界
始终优先于叙事顺滑。

## 1. 不可越过的边界

1. 不为制造“他们说／我说”而虚构阵营、争议或文献共识。
2. 不把单篇文献写成“学界普遍认为”，不把相近观点强行写成对立观点。
3. 归纳、引语和作者推断必须可区分；引号只包住来源原话，作者解释不得混入引号。
4. 每个事实、数字、引文、负面结果和限制仍由 Source—Claim—Evidence—Execution
   身份链约束。修辞动作不能替代证据。
5. 检查器只裁决字段、身份、状态和跨工件一致性。公允性、文气、说服力与真实
   对立程度由隔离评审判断。
6. 可使用本协议中的短句框架，也可按中文语序化用；它们是可选动作，不是句式
   配额或词频门。不设句式配额，也不以模板命中率评分。不得复制来源教材的长段
   文字或成套模板。

### 1.1 增量兼容：对话层不能挤掉研究层

v4.0 是对 v3 研究设计和 v2 方法执行的增量，不是替代。任务一旦涉及主张、证据、
反方或实质修改，答复按相关性保留五层闭环：

1. **判断／回应**：直接给当前可辩护结论及相对前人的实质增量；
2. **身份**：恢复 Position—Source—Claim—Evidence—Design—Execution—
   Case／Scope—Artifact 中本题实际触发的身份，不用框架标签代替内容；
3. **判别**：写出最强替代解释如何复制同一观察、双方不同的经验预期，以及当前
   材料已区分、未区分什么；
4. **传播**：负面发现、跨案例不一致或主张收窄必须进入结果、贡献、对话图、正文
   承重位置、生成视图和相应凭证，不能只补一句局限；
5. **停止条件**：明确允许／禁止的推断、降级措辞，以及哪些 `needs-review`、
   身份漂移、证据缺口或旧凭证未解决前不能 PASS。

不要求为简单问题堆砌无关字段；但某一层已被题目触发时，不能因加入对话术语而删掉
原有的来源溯源、设计、执行、负面证据、范围或哈希治理。

### 1.2 生成前承重事实卡与结果对象同一性

回应增量只能增加题面材料允许的关系、条件、机制问题或边界，不能偷偷更换待解释
结果。每次生成前只建立一张简短的内部**承重事实卡**，不要求输出表格或填满固定字段。
卡片先写用户真正要的成品，再把每个进入答复的声音冻结为同一组承重属性：
speaker（谁说）、result object（说的是哪个结果）、predicate strength（说得多强）、
scope（适用范围）和 epistemic status（已观察、来源解释、作者解释或仍待核验）。
题面给出的单位、案例／材料、关键数字、稳定定位、已知关系、未知项和禁止外推一并
保留；只有本题真正涉及来源处置、统计比较、活反方、读者行动或修改传播时，才把
相应关系补入卡片。卡片没有登记的关系不得在成稿中变成事实。

- 不得把题面中的“服务覆盖”换成“可持续服务”“服务质量”等相邻结果，再把换名
  当作贡献；若确需新结果，必须另有 Evidence、测量与用户确认。
- 只有“三地材料”时，不得擅自假定三地接受同一政策、同一任务或已经出现某个协调
  机制。共同处理、可比性和机制节点未核验时保持 `needs-review`。
- 文献只给出条件性结果时，可以追问机制，但不得把候选机制写成已观察事实。
- **命名交付身份优先**：用户要求替换或更新某个具名节点、Claim、段落或登记项时，
  标题或首个承重句先对该对象原有 result object 作出“保留／收窄／撤回／待核”之一
  的明确处置。支持证据、反例或反方若观察另一结果，必须另设身份；不得因其数字更
  具体，就把证据结果晋升为被替换节点的新结果。
- 不同结果之间只有在题面或已登记证据给出桥接测量时才能合并。例如命名节点谈
  “闭店前剩余量”，证据谈“末小时销量占比”，反方谈“排队影响末小时销量”，则
  反方当前只竞争解释末小时销量观察；它能否解释闭店剩余量仍是未决连接。输出须
  分别保留三个身份和这一未决关系，不能把“更谨慎”写成删除命名结果。
- 命名替换任务的最终反向核对固定问三件事：首句是否仍回答被点名对象；证据结果
  是否保持为支持／反例而未夺取节点身份；下一步记录是否同时覆盖命名结果、证据
  结果和两者的连接变量。任一为否则继续修订，不以完整反方段落抵消结果换名。
- 把第三问落实为不可合并的**三联闭合**：`命名结果—当前处置及其下一证据`；
  `证据结果—独立口径／出处及其连续记录`；`结果桥—成立状态及待核变量`。可用
  真实结果名代替 A、B 标签，但三项必须显式并列。证据结果已经有一个数值，不等于
  它可从下一步记录中消失；至少保留其样本／单位、指标、时段、数值、来源和是否继续
  同口径观测。只写“补数据”“关系未决”或把 B 散落在正文，均不算完成。交付前从
  三联的最后一项反向检查前两项，缺一即补，不再追加无关论述。
- 采用**最小充分回应**：先直接交付题目要求的贡献句、段落骨架、来源处置或修订差异，
  再补真正影响该交付的身份、反方和边界。最小充分不是最短；它指每项决定性交付、
  固定事实和必要边界均已有直接处置后停止。与本题无关的完整字段或竞争解释不因属于
  本协议而强行加入。

事实同一性优先于对话完整感。回应更丰富但改变结果对象、比较前提、材料角色或执行
事实时，按越界处理，不以更长的身份链抵消。

### 1.3 生成后承重闭合与命题强度所有权

题面或已核验来源不仅拥有“说了什么”，也拥有谓词强度和认识状态。锁定事实时一并
冻结在对应声音的 speaker、result object、predicate strength、scope 和 epistemic
status 中。

- 题面明确给出来源结论为“改善／导致／未发现”时，不因一般性谨慎自动改成
  “相关／可能／尚不清楚”；只有新证据或原来源边界要求降级时才能改变，并说明依据。
- 题面只说材料“支持机制存在”“与解释一致”或“部分区分”时，不得升级成
  “证明机制”“排除反方”或总体频率、平均影响和普遍范围判断。
- 公允归纳同时禁止无依据的增强和削弱。作者自己的推进另起一句，不能靠改写来源
  谓词制造研究空间。

草稿完成后只做一次**承重闭合**。从段末、意义句、行动建议和当前有界结论反向抽取
承重陈述，逐一对照事实卡：同一声音是否仍在谈同一结果、使用同一强度与范围；作者
解释是否混入来源声音；后句是否把精确结果换成相邻或上位概念；是否出现无依据的
静默增强、静默削弱或与前句矛盾；新证据影响的旧含义是否已从全部相关位置清除。
题目显式要求的成品和决定性细节必须有直接对应；压缩时只删除无关框架和重复说明：

- 来源核验要保留来源类型专属的身份、方法、版本和晋级／降级条件；
- 条件或机制主张要给出缺少何种反面观察、比较或过程痕迹时采用哪一句精确降级；
- 段落改写先交付可直接替换的片段，再附最短的归属、页码和传播核对项；
- 题目要求连接身份而未给现成 ID 时，可创建明确标为 `provisional`／“待登记”的
  稳定 ID；不得只写“某 Claim ID／Evidence ID”而让责任对象不可恢复。

完整不是字段越多，而是题目中的每一项决定性义务都有可执行处置，且末句没有改写
前文已经锁定的事实。

## 2. 来源进入对话的条件

每个最终来源先进入 `literature_registry.json`，再以 Source ID 参加对话。

进入 Dialogue Option Card 或 Position–Response Map 前，文献立场还须经过当前 `CR-*`／`SYN-*`：`CR-*` 区分作者结论、读者独立判断和用途边界，`SYN-*` 判断来源究竟支持、限定、矛盾、不可比还是只提供情境。对话图消费这些判断，不复制第二套逐篇评价；摘要／详情页只能代表作者公开位置，不能被写成“证据较强”“机制成立”或冲突裁决。

- CNKI 文献和官方原始记录按既有内容核验规则处理。
- 作为 `final-source` 的非 CNKI、非官方公开网络材料，必须填写 acquisition v2/v3
  `credibility`，并由其他已登记 Source ID 横向支持或质疑。
- 无法证明的网络可信度保持 `needs-review`；不得自动写成 PASS。
- 检索页、摘要线索或二手转述可以帮助寻找材料，但不得冒充已核验的最终来源。

开放网络来源的最小处置顺序是：先保留真实 channel／state／citation scope，再追溯
首次发布的原始报告或数据；核对作者、发布者、委托／资助／利益；分别用官方原始记录
和方法可复核的独立学术来源（如适用）检查事实口径与推断；用其他 Source ID 登记支持
和质疑。转述链、来源自引或“多个数字相近”都不构成独立横向核验。核验失败时可将材料
作为有明确归属的行业主张或研究对象，但不能把其中数字写成已证实事实。

网页数字若来自另一个报告或数据集，网页只保留为线索／转述身份；原报告核验后另建
唯一 Source ID。至少恢复样本与覆盖范围、指标定义和分母、统计时期、采集与计算方法、
修订记录，不能只因数字与官方材料接近就晋级。开放网络工作论文另登记当前版本、发布日期、
作者与机构、同行评议状态、方法透明度和利益关系；后续版本变化须重核。结论方向不影响
来源资格，方法透明但结论相反的材料同样进入可比性诊断、负面证据和主张校准。

反向材料先比较结果／估计对象、分析单位、时期、测量与分母、比较或识别、误差与
不确定性、版本和同行评议状态，不按支持篇数投票。官方统计可以核对事实口径，不能
代替对学术设计和解释的判断。`candidate-only` 或 `needs-review` 来源不能满足活动
Evidence ID 或最终 Claim：若材料可比且有诊断力，须收窄、修订或撤回主张；若不可比，
仍保留 Source ID、具体边界和排除理由。

### 2.1 无工作区直接答复

用户只要求处置一条来源、评议文献或贡献句、回应反方、解释意义，或做不改变含义的
局部表层改字时，不强迫其创建整套工作区；内部只运行一次生成前承重事实卡和一次
生成后承重闭合，不把完整论文的工件字段改造成直接答复配额。

若新证据将进入稿件、贡献句将替换实质主张，或任务改变标题、范围、方法、结果或最终
交付身份，则不再属于本节，转入 `manuscript_revision` 并按影响回 research/design/
execution/build。只有对这些内容作独立解释或评议、且不修改稿件时仍可 Direct。

- 只有存在能善意生成同一核心结果、并会改变当前结论的活反方时，才处理反方及判别
  材料。质疑前提与题面执行事实冲突时直接纠正，再保留真实范围边界；直接答复不为
  形式平衡强填“接受／拒绝／未决／当前结论”四项。
- 只有题目询问“为何重要、谁会关心、应采取什么行动”，或明确给出不同受众时，才写
  读者后果。按材料真实支持的受众数量作答；无实践含义时不制造政策通道，字数有限时
  先保住主交付、事实强度和推断边界。
- 只有答复正在作组间、时点、条件、交互等统计比较或推断时，才核对实际估计对象、
  比较、点估计、已有不确定性与显著性所属检验。描述性数字不要求补造检验，缺少
  对比估计时不得从单组显著或不显著推出组间差异。
- 只有保留直接引语、精确归属或局部语境决定含义，或用户要求可直接引注的文字时，
  才在可见答复中保留已有稳定定位；定位可以是页码、时间码、段落、条款、表号或档案
  号。普通转述仍保留来源归属，并可把定位放入引注；没有逐字核验或稳定定位时不用
  引号，也不补造页码。

输出先给用户要求的可替换文本，再给必要的证据边界；可替换文本使对象／行动、材料或证据、实质判断与必要边界之间的关系可恢复，具体排列按段落功能决定，不得用内部字段、作者意图播报或模拟审稿答辩代替成稿。可以从关键材料、引文或问题进入，不一律先写总结性短句。暂时删去“本文／本研究”动作句后仍应能够复述对象发生了什么、证据显示什么和当前判断。纯方法事实问答不强行套用本闭环；Direct 应用相关写作原则不要求新建工作区。

上述条件触发只适用于无工作区直接答复。完整论文的 research、contribution、build
与 audit 继续执行 Dialogue Option Cards、Dialogue Contract 和对话图；但这不构成正文
配额。正文只激活真实改变当前主张的读者后果与承重反方，允许没有显式反方段或只有
一个精确的读者更新。对已激活反方的接受、拒绝、未决和当前有界结论须能从论证链恢复。

## 3. Research：Dialogue Option Cards

`motivation_options_after_research.md` 必须先完成下表，再从卡片生成用户可见选项。
每个候选题一行，并与题目选项 ID 一一对应。

| Option | Response Target Type | Controlling Dispute/Unknown | Position/Source IDs | Candidate Response | Strongest Countervoice | Who Cares | So What | Missing Voice |
|---|---|---|---|---|---|---|---|---|
| O1 | explicit-dispute / common-assumption / literature-omission | 当前真正需要回答的分歧、共享前提或遗漏 | POS 描述及已登记 Source IDs | 作者可能采取的回应 | 对该回应最有力且有来源支持的异议 | 哪类读者会因此调整判断 | 理论、经验或实践上会改变什么 | 未进入材料的相关声音及处置 |

三种合法回应对象：

- `explicit-dispute`：至少有两个来源支持的不同文献立场；不能只凭语气制造“两派”。
- `common-assumption`：文献未必争论，但共享一个值得检验或限定的前提。
- `literature-omission`：既有研究系统遗漏一个问题、行动者、环节或边界；“没人
  研究过”必须改写为可核查的检索范围与具体遗漏。

遗漏不能因作者需要而升级为争论。只有出现针对同一结果的来源支持立场、相反解释及
可区分经验预期，才改标 `explicit-dispute`。补声音时既找受影响者和执行者，也主动
寻找能够善意生成同一观察的资格规则、材料质量、合规／防欺诈或资源约束等解释。

`Who Cares` 回答受影响的具体读者或行动者；`So What` 回答接受该发现后，理论
解释、经验判断或实践决策将发生什么变化。二者不能用“具有重要意义”互相替代。
每个候选只记录证据真正支持的读者—后果通道；可能没有独立实践通道，也可能只有
一个学术判断更新。不得为了显得重要另造第二受众或政策含义。凡保留的通道均按“具体
读者 → 当前默认／决策风险 → 本文改变什么 → 下一项研究或行动 → 成本／副作用 →
停止或不推广条件”闭合；一条精确通道优于两条泛化意义。

意义强度也按证据能力分层。理论意义须说明证据改变的是“机制可能存在”、发生频率、
平均影响还是普遍范围；实践意义须区分风险信号、定向核验／试点依据和广泛制度调整。
每项行动写出预期收益、成本或副作用及不得升级推广的条件。单案例支持机制可能存在，
不等于证明机制、估计普遍程度或授权全面改革。

研究确认后，`confirmed_motivation.md` 至少登记：

| Field | Content |
|---|---|
| Controlling Dialogue/Unknown | 已确认的主控争论、共享前提或遗漏 |
| Response Target Type | 三种合法类型之一 |
| Position/Source IDs | 文献立场与已登记 Source IDs |
| Initial Author Response | 当前作者回应；不是最后结论的夸张预告 |
| Strongest Countervoice | 对当前回应最有力的来源支持异议 |
| Who Cares | 具体读者或行动者 |
| So What | 理论、经验或实践后果 |
| Missing Voice | 遗漏声音及补入、限制或不代言的处置 |

## 4. 公允归纳、引文和声音

对话开始前先区分三种声音：**研究对象／原始材料的声音、二手研究的解释声音、作者的综合判断**。关于理论家、制度文件、档案、数据或原研究“说了什么／显示什么”的命题，优先链接最接近该命题的原典、正式文件、原始档案、原始数据或原研究；二手文献负责说明学界如何解释、争论和评价。原始材料暂不可得时，保留转述链和 `needs-review`／降级措辞，不把二手转述写成对象原话。

来源接近性不是按“原始来源数量”评分。原始材料拥有内容命题，二手研究拥有其学术解释与位置；二者可以共同承重，但不能互相冒充。政治理论、思想史和政策文本研究中，规范性或思想性判断尤其须由可获得的权威原文／经典原典先行，二手研究再承担谱系和争论定位。

公允归纳至少满足四项：

1. 用来源本身认可的术语说明其主张；
2. 保留该主张的条件、对象与证据类型；
3. 不用作者的结论倒写前人“错误”；
4. 紧邻 Source ID 或正式引文归属。

还须保留来源谓词的原始强度：既不把“改善”无故改成“相关”，也不把“提示”写成
“证明”。需要更谨慎时，把限制放在作者回应或推断边界中，而不是悄悄改写来源声音。

作者回应若把条件性发现推进为机制问题，必须另列尚未区分的替代解释和降级规则。
例如，材料只能显示共变时，可写“与该解释一致”或“提示可能边界”，不能把待检验
环节倒写为来源已经证明的机制。跨案例不一致和负面观察必须改变范围或贡献，而非只
作为附带备注保存。

条件／机制措辞按实际证据逐级使用：

1. 只有共变，且缺少反面观察或比较：写“相伴随”“随……而异”或“与该解释一致”；
2. 条件已测量，并有反面观察和部分过程材料：可写“支持其可能构成条件性环节”；
3. 实际设计已区分主要替代解释：才可在登记范围内写“构成条件”或“产生影响”；
4. “必要”“唯一”“证明”另需相应的识别与执行契约。

缺少无处理观察、过程痕迹或共同原因尚未排除时，答复应直接给出替换后的降级句，
不能只写“谨慎表述”。

只有段落正在作统计比较或推断时，才复核实际估计对象、比较对象、点估计、已有
不确定性以及显著性属于哪一个检验。单组效应显著或不显著，不能自动推出组间差异、
交互、顺序或条件差异显著；没有相应对比估计与不确定性时，只报告实际检验过的对象，
不为凑齐统计字段补造信息。

原话本身具有证据、概念辨析或声音价值时，主动选用恰当的语境性直接引语，回到同一篇原始文献恢复其问题意识、论证对象、因果或逻辑结构与限定条件，不孤立摘取名言。让读者能够识别说话者、相关语境
和作者对引语功能的解释即可，不规定三句或固定次序；有力材料可以先出现，随后自然说明它使哪项判断被支持、区分、修正或反驳，而非每次机械追加“这说明”。直接引语须逐字核验，并在已有
稳定定位时保留页码、时间码、段落、条款、表号或档案号。普通转述同样保持归属，定位
可进入正式引注而不必反复塞入正文。孤立引语、无归属引语、补造定位和用引语代替
分析均不合格。

以下框架只示范回应动作，可按需重组为长句、短句或跨句推理，不是固定段首：

- “关于 X，SRC-001 在 Y 条件下支持 A；本文接受 A，但把问题推进到 B。”
- “这些文献并未形成两派争论，而是共同把 C 当作前提；本文检验该前提在 D
  条件下是否仍成立。”
- “SRC-002 指出的并非 A 毫无作用，而是 A 不能单独解释 B。本文的分歧也止于此。”
- “这里先报告材料显示的 E；由 E 推到 F 是本文的解释，不能归给被引作者。”

如一句话中读者无法判断是来源陈述、引语内容还是作者推断，拆句并补明归属。段落
完成后使用 §1.3 的一次承重闭合：尤其核对末句是否仍保持各声音的归属、结果对象、
谓词强度、范围与认识状态，以及“共同、不同、遗漏、争论”等元评述能否由前文推出。

## 5. 作者回应与最强反方

合格回应增量须在同一结果对象上，明确新增至少一种可操作变化：分析单位、过程阶段
或时序、条件、测量、比较，或产生不同预期的竞争解释，并指出相应材料或可观察后果。
只说“进一步研究机制／边界”而没有节点、材料或判别后果，仍是占位语。概念或规范
研究可用概念区分、前提、反例或决策后果完成同一要求。

辨析要说清相近概念或判断各自在什么条件下成立，不能以“提供视角、具有启示”代替作者的判断。批评一项观点时具体说明它解释不了什么、漏掉哪个前提，或沿其自身逻辑还会导出什么问题；锋利由推理承担，不靠尖刻措辞或攻击作者。跨文本、跨时代或跨学科联系须说明相通的层面、条件、差异与解释收益；启发性类比不能冒充独立互证，词语相似不能冒充思想同构。关系仍由现有来源、综合命题与 warrant 支持，不能从语言范例推生新事实。

允许的回应模式为：

- `agree`：接受前人判断，并说明本文为何需要再次确认或应用。
- `disagree`：给出可判别理由和反证，不靠态度词完成反对。
- `agree-and-qualify`：承认有效部分，同时限定条件、范围或机制。
- `reframe`：改变问题单位、因果顺序或解释层级，并说明为何更合适。
- `synthesize`：指出不同立场分别解释哪一部分，并建立可检验的组合关系。
- `extend`：在不否定原结论的前提下推进新对象、环节、机制或边界。

最强反方首先是**论证后台的压力测试**，并不自动成为正文中的一段模拟审稿答辩。最终稿通常把后台结果转译为“已有成果已经解释什么—仍留下哪个同一对象上的问题—本文用什么材料作何种有限推进”。只有存在有来源支持的公开争论，且直接呈现反方有助于读者理解判别证据时，才显式展开；此时也须按来源归属写成学术对话，不能用“最强反对意见认为”“这一质疑部分成立”等作者自问自答代替文献关系。

Build 前由 Materiality Compiler 决定它是否跨过 prose firewall。只有反方有已登记来源、
能够生成与当前 Claim ID 相同结果且处于同一分析阶段、会改变该主张，并有判别证据时，
才进入 ProsePacket；否则 `manuscript_action=omit`，留在后台压力测试中。没有满足这些
条件的替代解释时，ProsePacket 中反方数量为 0 是合法结果，不能用“可能有审稿人质疑”
激活一个反方段落。

同理，证据边界表属于后台控制。正文只在边界实际改变当前主张的位置说明一次完整理由，其他位置用短限定或回指。孤立的“材料只能支持什么／不推断什么／贡献限于什么”段落如果不改变当前判断或章节推进，应合并、移位或删除。

最强反方必须是对最终立场真正构成压力的版本，并链接到 Position ID。先承认它
解释得最好的现象，再交代判别证据、让步范围和仍未解决的部分。反方没有被彻底排除
时，用“在已观察场景中更符合”“尚不能区分”等校准措辞。

完整论文或工作区内已激活的承重反方处置必须能恢复四项：**接受什么、拒绝什么、仍保留
什么未决、当前可直接采用的有边界结论**。无工作区直接答复只在活反方真实影响结论
时自然交代其中适用的判断，不强制四标签；质疑前提已被执行事实否定时直接纠正。
方法上的不可比性可以构成边界，但若存在能产生同一结果的共同原因或替代过程，应
优先把它作为最强反方；不能用抽象谨慎替代真正有诊断力的竞争解释。

这里的“能恢复”约束论证完整性，不规定正文表面结构。四项可以分别落实为对既有成果的公允归属、判别性证据、校准后的正面判断和集中边界；不得为了让审计者逐格核对而把它们写成“反方认为—本文接受—本文拒绝—本文限定”的作者答辩段。若删去这类自我说明后对象、证据和结论也随之消失，说明后台控制已经取代研究内容。

反方处置不能停在 `Concession`、`Difference` 等字段名。至少说明：反方通过什么
过程能够产生与作者解释相同的核心观察；作者解释与反方各自预期出现什么不同的时序、
内容、比较或反例；当前 Evidence／Execution 支持了哪一项、缺少哪一项，以及下一项
最有诊断力的材料是什么。若只能部分区分，就保留共同作用或归因未决。

可化用：

- “最有力的异议不是否认 E，而是认为 G 已足以解释 E。”
- “该异议解释了 H，因此本文保留 H；但它预期 I，而 EXE-001 观察到 J。”
- “这并不证明反方在所有条件下错误，只把其解释范围限定在 K。”

## 5A. 论证谬误清单

最强反方处理（§5）针对的是"别人怎样反驳我"；本清单针对的是"我自己的论证在哪里先漏了"。
它在 build 前由作者自查，在 audit 由 Contribution／Clarity Reviewer 复核。每条给中文稿常见的识别
句式、修复动作，以及它归到 §5 的哪一种反方处理或 `three-questions-standard.md` 的哪一条判准。
清单不是词频门：命中句式只是线索，是否构成谬误由论证链判断。

1. **循环论证**
   - 识别信号："X 之所以有效，是因为它发挥了 X 的作用""治理效能提升体现为治理能力增强"——结论换个说法当理由；概念定义里已包含要证明的结果。
   - 修复：把因与果写成可分别观察的两个对象（Gerring 四要件第 1 条，`three-questions-standard.md` §4），补一个不依赖结论的独立证据。
   - 对应：§5 增量要求——回应必须在同一结果对象上新增可操作变化，否则是占位语。
2. **以描述冒充解释**
   - 识别信号："呈现了……的运行逻辑""揭示了……的内在机理"，正文只有阶段划分与特征归纳，没有任何"若无 X 则 Y 如何"的比较。
   - 修复：要么降级为描述性贡献并给出分类与比较基准（`three-questions-standard.md` §5 允许，且在知识薄弱领域更有价值）；要么补反事实与比较（§4 第 3、4 条）。
   - 对应：`engine/contribution.md` 伪贡献第 8 条；§5 `agree-and-qualify` 的限定写法。
3. **以频率推"应当"（事实—价值跳跃）**
   - 识别信号："多数地方已采取 X，因此应当推广 X""既然 Y 普遍存在，就应承认其合理性"。
   - 修复：把价值前提写出来（`method-routing.md` 规范路线要求分开价值与事实前提），说明由事实到建议还需要哪项评价标准与受影响主体判断。
   - 对应：§3 `So What` 分层——风险信号、定向试点依据与广泛制度调整不能互相替代。
4. **生态谬误与个体谬误**
   - 识别信号：用省级面板结果解释"干部个体的行为动机"，或用个体访谈推断"该地区整体治理模式"；分析单位在结论句里悄悄换层。
   - 修复：在承重事实卡里冻结每个声音的分析单位（§1.2），跨层推断须另有连接材料或明确写成假设。
   - 对应：`three-questions-standard.md` §0 系统思维"在单层材料上作跨层推断"的警告；§5 `reframe` 须说明为何改变单位更合适。
5. **时序即因果**
   - 识别信号："政策出台后 X 指标上升，表明政策产生了效果""改革之后……随之……"，没有对照、没有政策前趋势或竞争解释。
   - 修复：给出反事实（同期未处理单位、政策前趋势），或把措辞降到"相伴随""与该解释一致"（§4 措辞层级 1）。
   - 对应：Gerring 四要件第 2–4 条；§5 最强反方优先选"能产生同一结果的共同原因或替代过程"。
6. **稻草人**
   - 识别信号："传统观点简单地认为……""既有研究忽视了……"，被批评者的原文找不到这种简单版本；对手只以一句概括出现，没有 Source ID。
   - 修复：按 §4 公允归纳四项重写对手立场，用对方认可的术语和条件复述；写不出可成立的复述就撤回该对立。
   - 对应：§1 边界第 1、2 条；anatomy §3.2"对话对象被公正复述"。
7. **诉诸"学界公认"**
   - 识别信号："学界普遍认为""已成共识""众所周知"——之后只引一篇或不引。
   - 修复：要么给出至少两个独立来源并说明其条件（`explicit-dispute` 与 `common-assumption` 的登记要求），要么改写为"SRC-00n 在 Y 条件下支持 A"。
   - 对应：§1 边界第 2 条；`critical-reading-and-synthesis.md` §五.4 不把同源引用当多重证据。
8. **选择性引证**
   - 识别信号：只引支持本文结论的研究，反向结果不出现；"大量研究表明"后面的清单全部同向；负面结果只在局限节一句带过。
   - 修复：反向材料先做可比性诊断（§2），可比且有诊断力则收窄主张；`Missing Voice` 登记未纳入的声音及处置。
   - 对应：§5"接受什么、拒绝什么、仍未决什么"必须能恢复；§6.4 负面证据不得静默删除。
9. **概念偷换与滑坡**
   - 识别信号：引言说"治理效能"，结果测的是"满意度"，结论又回到"效能"；或"若允许 X，就会导致 Y，进而 Z"而每一步都无证据。
   - 修复：核心术语受控重复（§7），每次换词都要说明是否同一结果对象（§1.2 结果对象同一性）；滑坡链每一环单独给证据或改写为条件假设。
   - 对应：§1.3 承重闭合"后句是否把精确结果换成相邻或上位概念"；anatomy §3.6 概念拉伸。
10. **幸存者偏差与沉默证据**
    - 识别信号：只研究成功案例、典型经验、"先进地区"，据此总结"成功经验"；史料只用留存并被整理出版的部分。
    - 修复：说明案例／材料的选择与保存过程（`critical-reading-and-synthesis.md` §三 `selection-survival-bias`），补失败案例或反面材料，或把结论限定为"在已观察的成功案例中"。
    - 对应：`research-gap-diagnosis.md` 阻断原因 `biased-coverage`；§5 让步范围。
11. **以否定对手代替证明自己**
    - 识别信号："既有解释无法说明 X，因此本文的解释成立"——反驳了 A 就当作证明了 B。
    - 修复：本文解释须有自己的判别预期与证据（§5"作者解释与反方各自预期出现什么不同的时序、内容、比较或反例"）；对手失败只缩小候选集，不确立本文。
    - 对应：§5 `disagree` 模式要求可判别理由和反证，不靠态度词。
12. **复合问题**
    - 识别信号："为什么 X 政策既提高了效率又损害了公平"——两个待证前提被打包进一个问题；研究问题里已预设了答案。
    - 修复：拆成可分别检验的命题，每个命题各自登记 Claim；未证实的前提改为待检验假设。
    - 对应：`three-questions-standard.md` §2"问题一开始就没有厘清"红旗；`research-question-design.md` 五类问题。
13. **以理论标签代替机制**
    - 识别信号："这体现了新制度主义的路径依赖""可用委托—代理理论解释"——贴标签后不再说明具体行动者、约束与环节；术语出现即视为解释完成。
    - 修复：把标签展开为"什么主体在什么条件下通过什么环节产生什么结果"（anatomy §3.8 理论／假设写法），并给出该机制在材料中的可见痕迹。
    - 对应：`engine/contribution.md` 伪贡献第 6 条（命名无机制）；§5 增量要求中"指出相应材料或可观察后果"。
14. **以政策文本推行为效果**
    - 识别信号："《意见》明确要求……，标志着 X 机制已经建立""各地纷纷出台……，说明 Y 已成为制度实践"——把文件颁布、机构挂牌、试点名单当作行为改变或结果实现的证据。
    - 修复：区分政策文本、组织执行与行为后果三层，每层各要证据；文本分析只支持"政策意图与话语"层面的主张（`method-routing.md` 文本任务：关键词频率不能自动代表态度、行为或因果）。
    - 对应：`three-questions-standard.md` §5"预设也要检验、行动者自述不照单全收"；§5 最强反方把"执行落空"作为替代过程。

自查方式：写完每个承重段，在 §1.3 承重闭合时顺带过一遍本清单；只处理真正命中的条目，不为每段写十四项说明。
审计发现的谬误按 anatomy §4 补充诊断纪律转成标准 Finding，并附抬档路径（重做论证／补证据／收窄主张）。

## 7. Build：元评述与连贯推进

元评述只在能帮助读者定位论证动作时使用，例如说明“这里先区分两种解释”“下一节
检验的是它们的不同预期”。不要向读者播报写作流程、审稿意见或模板名称，也不要把
对话图中的“最强反方、让步、拒绝、未决”和证据审计字段逐项翻译成正文。正文前台
优先呈现研究对象／行动者及其变化、相应材料或证据、实质判断，以及真正改变该判断的
边界；作者回应和框架名称只能服务于这条主线，不能成为连续段落的主语。

每一写作单元只向隔离 writer 传入验证后的 `avereth-prose-packet/v2`；packet 的内容边界、受保护语义原子、Clarity Editor 的五个动作、门禁链与 `avereth-clarity-edit-ledger/v1` 合同以 `academic-prose.md` §1.2 为正本，本文不重述。对话图对写作只加两条约束：作者回应与框架名称不能成为连续段落的主语；新事实、新引用、新案例或更强推断都必须回到事实拥有阶段，不能在写作或清晰度编辑中出现。

Build 还要维护研究对象的连续性和章节答案密度：摘要、引言、核心分析与结论始终回应
同一研究对象，分析框架只承担解释功能；引言给最低限度答案，核心分析完成定义与证据，
结论先收束实质判断。对话关系可以跨章传播，同一组完整答案不得在各章依次复刻。
逐段暂时删除只说明“本文／本研究做什么或不做什么”的句子后，读者仍须能说出对象发生了
什么、证据显示什么以及作者据此作出什么判断；否则重建这些关系，不机械统一为对象—证据—判断—边界的表面顺序。

连贯推进优先使用：

- 关键术语的受控重复；
- 明确指称（“这一条件”“上述判别结果”）；
- 前句旧信息到后句新信息的衔接；
- 段末交代当前结果为下一段留下什么问题。

连接词不能掩盖缺失的逻辑关系。若“因此”两侧没有证据—担保关系，应补担保或删除
连接词。

## 8. Audit：两层裁决

`dialogic_argument_check.py` 的硬门只检查：

- Source、Position、Claim、Evidence、Execution 身份是否注册并相互连接；
- 必填字段、合法枚举、最少行数和状态是否关闭；
- `confirmed_motivation.md`、`confirmed_contribution.md` 与对话图是否一致；
- 实质修改是否登记复核并传播。

隔离评审另行判断：

- 归纳是否公允，是否存在虚假争论或稻草人；
- 引文、来源声音与作者声音是否清楚；
- 作者回应是否产生实质增量；
- 最强反方是否真的“最强”；
- `Who Cares` 与 `So What` 是否具体、有区分；
- 文气、节奏和说服力是否适合目标场景。

Clarity Reviewer 只能从最终稿独立评审，不读取 `academic_prose_audit.md`、
`dialogic_argument_map.md` 或审稿／回复工件。它先在承重单元复原“发生什么—为什么—证据如何支持解释—改变什么认识”，再复原研究对象、具体问题、实质答案、最强证据和推断边界，以及谁在说什么、作者如何回应、为何重要。它按功能区分真实负面结果、有用概念对比、范围排除、作者意图防守和评审／流程语言；前两者不因否定表面而被删除，范围优先正面表达，作者防守改写，评审／流程泄漏硬失败。它还要检查隐性“质疑—让步—回复—限定”、评论顺序、重复边界和后插补丁接缝。任一项复原失败本身就是稿件问题；不得反向要求正文写出四格反方答辩。

# Problem Arc projection

When `literature_analysis.json` contains `problem_arc`, the Dialogic Argument Map adds a Problem Arc Projection with State ID, Live Question, Argument Action, Updated Problem, Authority Refs, Branch/Disposition, and Status. The projection must match the canonical analysis; it cannot mint a new transition or silently drop a major branch. See [`rhetorical-architecture.md`](rhetorical-architecture.md). A legacy analysis without `problem_arc` does not require the table.
