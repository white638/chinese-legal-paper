# 文献充分性：数量积累、核心深读与学术对话

这份协议回答的不是“引用多少看起来像论文”，而是“一个正常学者为承担当前问题，至少应完成多少检索、筛选、阅读和学术对话”。数量、深读和覆盖是三个并列条件，任何一个失败都不能由另两个抵消。

## 一、三层积累

- `screened`：真实运行过的广泛检索与筛选空间。应能看见主要流派、奠基研究、近期前沿、竞争解释、真实反方和负面结果。
- `final-source`：可能进入正文的合格来源。每篇均已核验内容，说明用途、相关责任及允许／禁止主张。
- `core-reading`：承担理论、方法、关键事实、核心结果、反方或冲突裁决的来源。必须取得合法全文，执行完整七步深读并进入 `SYN-*` 综合。

三层身份写入 `literature_analysis.json.literature_sufficiency`。final 是 screened 的子集，core 是 final 的子集。所有 final 都有阅读记录。core 使用 `reading_depth=core`，机械要求合法全文、完整七步并至少进入一个 `SYN-*`；非承重背景来源使用 `reading_depth=background`，只填写用途、内容摘要、使用边界、定位锚点和允许／禁止主张，不复制七步长表。

## 二、目标刊动态基线

1. 冻结目标刊、文章类型和目标稿件字数。
2. 收集同刊、同文章类型、篇幅在目标稿件 70%–130% 之间的论文。
3. 优先使用当前年向前覆盖三年的样本；不足五篇时扩展到五年。扩展后仍不足五篇，不能声称取得动态基线。
4. 每篇保留 Source ID 与 DOI、稳定 URL 或本地 SHA-256，并记录年份、篇幅和合格学术参考文献数。官方文件、新闻、档案和原始数据不计入该数。
5. 对至少五篇合格样本的参考文献数排序，nearest-rank 的第 25 百分位为 `ceil(0.25 × n)` 位置。例如五篇为 20、25、28、31、40，则 P25 为第 2 个值 25。
6. 将动态基线与经核验的用户／期刊最低要求比较，取最高值。外部要求只接受 `authority=user|venue`，须保存明确最低数与确认或官方依据。

## 三、无法对标时的任务兜底

| 任务 | 最低合格学术文献 |
|---|---:|
| 完整期刊论文 | 25 |
| 会议论文或研究报告 | 15 |
| 选题任务 | 12 |
| 研究设计任务 | 20 |

审计任务只报告相应差距，不为旧稿补造引用。修订任务只有补足适用基线并通过全部覆盖门，才可取得完整 output PASS。

## 四、什么可以计数

只有同时满足以下条件的唯一作品计数：

- `citation_scope=final-source`；
- 有可核验且可去重的作品身份：DOI、稳定原文 URL、本地文件 SHA-256，或完整题名—首位作者—年份；
- 摘要、详情页或全文至少一种内容核验完成；
- 来源属于学术作品，而非新闻、官方材料、档案、原始数据或普通网页；
- 相关性已映射到问题、立场／理论、主张、方法或真实反方责任；仅标“事实、结果、背景、边界”而不说明它服务哪个问题／主张／方法，不能计入学术对话数量；
- DOI 优先去重；无 DOI 时按规范 URL，再按题名—首位作者—年份去重。

题名命中、结果页、BibTeX、元数据、未读候选、重复版本和无关凑数不计。原始材料可保留为 final-source 支撑事实，其阅读与引用仍受核验门约束；它只是不计入学术文献数字，也不能承担下面的学术争论覆盖。

## 五、数字之外的覆盖门

以下五项均须完成：主要立场、真实反方、奠基链、近期变化、方法责任。每项不是一个布尔自报，而是 `status=covered`、至少一个**可计数的学术 final Source ID**、至少一个 `SYN-*`、至少一个交叉命中的 `core-reading` 和实质理由的映射。`current_qualified_count` 必须等于控制器按身份、去重、内容核验、相关责任和学术属性重新计算的数字。然后连续运行至少两轮有明确目的、在注册表中 `status=complete` 且 Query ID 不重复的定向补检；最后两轮都不得出现新的主要立场或决定性证据类型，并将新增来源作用记为 `verification`、`boundary`、`known-gap` 或 `none`。若仍不断暴露全新板块，research 尚未饱和。

### 引文边与机器核验

奠基链和真实反方两项在注册表登记了 `edges`（见 `acquisition-registry.md` 5.3）后不再是自报：

- **奠基链**：覆盖条目的 `source_ids` 必须经核验的 `cites` 边连通（可经由任何已登记来源中转；只列一篇时至少要有一条触及它的 `cites` 边）。
  不连通是硬失败——一串名篇彼此之间没有被核实的引用关系，不构成谱系。条目可选 `edge_ids` 指明所依据的边，填写即须解析到注册表。
- **真实反方**：至少应有一条 `stance=critical` 的边触及所覆盖的来源；没有时只给警告，因为并非所有对立立场都互相引用，
  但此时反方是自报的，评审应据 `SYN-*` 的冲突解释另行判断。
- 注册表没有任何边时，两项都以警告提示"自报"，不阻断旧工作区；新工作区在滚雪球与全文精读时就应登记边。
- 边只证明关系存在与立场，不证明来源内容已核验；来源仍各自走状态与证据等级。

## 六、穷尽性语料例外

只有封闭语料或客观极窄领域可申请。必须公开完整检索边界与纳入规则，保留穷尽检索 Query ID 和总体穷尽证据，证明合格总体小于兜底线，列出并纳入全部合格作品，记录 `reason=closed-corpus-exhausted`，并取得带依据的用户确认。`included_source_ids` 必须与实际计数的合格 final-source 完全一致；期限、经费、登录失败或获取困难均不能降低数字。

## 七、失效边界

v2 绑定承重来源的身份、权限、核验、相关性、用途和文件哈希。它不绑定未采用候选或查询备注，因此继续广泛检索不会无故使整篇失效；一旦承重来源变化，回到 research 重新核验数量、权限、覆盖和综合。
