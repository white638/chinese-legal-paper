# 研究质量三问与设计匹配协议

> **LEGACY ONLY**：本文件只解释 v1–v3 旧矩阵字段，不参与任何 gate；2026-08 之后创建的工作区不必阅读。

本协议把高质量社会科学研究的核心顺序落成硬工件：先回答“已经知道什么”，再回答“还要认识什么”，最后回答“如何认识”。它约束研究问题、理论、概念、证据与设计的匹配，不把定量/定性、归纳/演绎、解释/诠释排成高低等级。

> **v3.1 状态**：本文件保留旧字段的含义和迁移解释，不再定义独立硬门。
> 权威设计真相是 `research_design.json`，执行规则见 `research-design-spine.md`；
> `knowledge_design_matrix.md` 由 `research_design.py render` 生成，禁止手工维护。
> `research_quality_check.py` 仅用于诊断旧矩阵，不能代替 v3.1 design gate；
> 新执行事实由 `method_execution.json` 持有。

> **思想源流**：三问序与判准出自内尔高《怎样的政治学研究是高质量的?》（管玥译，
> 《国外理论动态》2017 年第 1 期）——判准全文、因果四要件、设计三经验法则、增量判例
> 与两分法止战见 `three-questions-standard.md`（指导思想层）；本协议是其硬门与工件契约层。

## 使用位置

1. 选题阶段先按 `topic-induction-deduction.md` 与 `research-question-design.md` 建 `topic_induction_deduction_matrix.md`，不要在用户选择前替其锁定单一研究问题和主张类型。
2. acquisition/research 通过且用户在 `question_confirmation` 确认精确问题后，进入 design，建立 `research_design.json`。
3. 用 `research_design.py render` 生成本文件所述的人类可读矩阵视图。
4. 执行、写作和审计时重跑 `research_design.py validate --write`，并按当前阶段分别传入 `--stage execution`、`--stage build` 或 `--stage audit`；问题、数据或方法发生实质变化时先更新 JSON 契约。

## 三问顺序

- **已经知道什么**：只登记有来源支撑的命题，并标可信程度、争议和适用边界。题名命中不是知识；摘要、详情页、全文和原始材料的证据等级要区分。
- **还要认识什么**：把“未知”写成可回答的研究问题和单一新增知识，不用“重要但鲜有研究”冒充缺口。先检验低研究度究竟来自发表时滞、术语错配、相邻文献覆盖或贡献不足，再按 `research-gap-diagnosis.md` 选一个主要落点与阻断原因，链接当前 `SYN-*`，说明具体未知、研究责任、撤回条件以及答案相对现有知识改变了什么。
- **如何认识**：先定主张类型和知识成熟度，再选设计。方法必须制造回答问题所需的比较、变异、反事实、过程证据或规范推理链。

## 必交工件模板

生成的 `knowledge_design_matrix.md` 使用以下三列表。`证据/理由`列对已知和未知引用注册表中真实存在的 `Sxx` 或已有工件；其他行给出可审计的设计理由，不写“按惯例”“较为合适”。下表用于理解和迁移，不是第二份可编辑 schema。

| 字段 | 内容 | 证据/理由 |
|---|---|---|
| 已知命题与可信程度 | 已被何种研究反复支持，哪些只是暂时判断 | Sxx/来源 URL/`sota_gap_map.md` 定位 |
| 未知、争议或经验异常 | 现有解释冲突、缺失或预测失败之处 | Sxx/来源 URL/`sota_gap_map.md` 定位 |
| 空白真实性与低研究替代解释 | 原字段内写两轴诊断：`corroborated` 状态、一个主落点、阻断原因、具体未知、`SYN-*`、替代解释、研究责任和撤回条件 | 当前 `SYN-*`；Source/Query/Collision 身份由上游注册表与综合单元解析 |
| 知识成熟度 | `探索期` / `发展期` / `成熟期`，并解释判定 | 概念、描述、理论和证据当前积累 |
| 研究问题 | 一个可回答的问题，不是话题 | 它如何由上一行未知推出 |
| 研究问题主类型 | 只选一个主类型：`描述性`、`解释性`、`预测性`、`操作性`、`规范性`；复合问题可另记一个次类型 | 合格答案必须交付什么；不得按疑问词机械分类 |
| O-T-I-P-R 研究问题卡 | `O=对象；T=时间；I=领域；P=视角；R=强关系/弱关系：核心联系` | 五项如何共同收窄问题；解释性、预测性默认强关系 |
| 预期新增知识 | 回答后相对现有知识新增或修正什么 | 对话对象和差异点 |
| 主张类型 | 只选一个主类型：`描述/概念`、`诠释/理解`、`因果效应`、`因果机制`、`规范论证`、`理论/综述` | 为什么该类型足以回答问题 |
| 理论视角与核心概念 | 理论选择、概念内涵/外延及近邻边界 | 理论为何能聚焦材料；不得称“数据自己说话” |
| 分析单位、对象与可比性 | 单位、时间/空间、语义与功能等价性 | 为什么可比较；不等价处如何处理 |
| 范围条件与边界 | 结论可能成立及可能失效的条件 | 已知限制、样本/案例边界 |
| 设计选择及匹配理由 | 数据、案例、方法和关键步骤 | 为什么能回答该主张，而非只写方法名 |
| 变异、比较或反事实 | 观察值从哪里来，比较基准是什么 | 常量不能单独支撑模式或因果推断 |
| 替代解释或反对论证 | 最强竞争解释/反方论证及区分办法 | 需要什么证据才能排除或保留 |
| 可证伪或修订条件 | 什么发现会使主张失败、收缩或改写 | 预先写清判据 |
| 推断上限 | 本设计最多允许声称什么、禁止外推什么 | 与样本、材料、比较和证据等级一致 |
| 设计局限及补救 | 当前设计最脆弱处与补证/收缩方案 | 不用修辞掩盖缺口 |

在同一表末尾追加与主张类型对应的分支行。

## 五类问题的附加字段

问题类型回答“要完成什么认识任务”，主张类型回答“用什么知识主张来完成”；二者不得混为一谈。除规范性外并非一一对应，具体路由见 `research-question-design.md`。

| 问题主类型 | 必须追加的字段 | 最低逻辑 |
|---|---|---|
| 描述性 | `描述增量与还原边界` | 说明新现象、概念或史实为何仍不清楚，采用何种分类/材料规则，答案相对既有描述新增什么 |
| 解释性 | `待解释关系与区分性预期` | 写清强关系、方向/机制、条件及至少一个可与竞争解释区分的观察 |
| 预测性 | `预测对象、时域与基线`、`不确定性、验证与更新` | 说明预测到何时、以什么基线/模型/情景为依据，如何表达不确定性并用新观察校验更新 |
| 操作性 | `行动主体、目标与约束`、`行动杠杆、可行性与评价标准` | 方案面向谁、实现何目标、受何约束，哪些杠杆有证据支持，如何评价成败及处理风险 |
| 规范性 | 复用规范论证分支的四项字段 | 公开价值前提、推理链、最强反方及经验/制度约束，事实研究不替代“应当”的论证 |

## 六类主张的分支要求

| 主张类型 | 必须追加的字段 | 合格设计的最低逻辑 |
|---|---|---|
| 描述/概念 | `概念与分类规则`、`比较基准与变异` | 分类有内涵、外延和区分度；新描述相对既有知识有增量；至少有跨单位、跨时点、子案例或明确反事实比较 |
| 诠释/理解 | `行动者意义与语境`、`研究者位置与反身性` | 先重建行动者意义，再说明理论视角如何选择和组织材料；自述动机不自动等于真实原因 |
| 因果效应 | `原因、结果与方向`、`时间顺序`、`反事实与识别`、`效应形式与异质性` | 区分因果两端和方向，说明无原因时会怎样，以可比变异控制合理替代解释；平均效应不冒充普遍定律 |
| 因果机制 | `机制链与可观察含义`、`过程证据`、`竞争机制` | 逐环节说明原因如何产生结果，用过程观察、跨时段/子案例/比较案例区分竞争机制；只有首尾共变不算机制证据 |
| 规范论证 | `规范前提`、`规范推理链`、`最强反方论证`、`经验与制度约束` | 价值前提公开，推理步骤可检查，认真处理反方，并用事实检验可行性而非伪装成经验因果 |
| 理论/综述 | `语料范围与纳入规则`、`综合逻辑`、`可检验命题或知识地图` | 语料边界可复核，综合不等于罗列，产出清晰概念、命题、争议结构或未来可检验路径 |

## 成熟度与设计决策

- **探索期**：概念、分类或基本事实仍不稳。优先可信描述、概念澄清、探索性个案或语料建构；若直接做因果效应，必须给出分阶段先导设计和足够理论基础。
- **发展期**：已有若干解释但机制、边界或测量有争议。适合比较个案、过程追踪、混合方法、竞争假设检验或测量改进。
- **成熟期**：概念语法、测量和因果命题已有较强积累。可集中估计效应形式/强度、异质性和外部边界，也可用关键案例挑战成熟理论。

## 审计判据

- 不因方法标签判高下；只看设计是否提供该主张所需的观察与推理。
- 单案例不是天然低质，但若要概括模式或因果，必须提供跨时段、子案例、过程观察、反事实或外部比较中的至少一种真实变异。
- “有些……有些……”只能作为一个比较性问题：各项必须共享一个结果变量和可比分析单位。核心案例可以承重、对照案例可以简写，但二者不能被拆成两个并列研究问题。
- 按答案任务而非疑问词判断问题类型；研究问题卡必须显式包含 O、T、I、P、R，且说明关系是强还是弱。解释性、预测性若未写强关系，返回 research 的问题确认检查点；描述性、操作性、规范性弱关系问题不得被强行改写成伪因果问题。
- 预测性问题无明确时域、基线、不确定性和验证更新规则，操作性问题无主体—目标—约束—杠杆—评价链，规范性问题无公开原则和最强反方时，均不得通过。
- 不把不同制度形式预设为同一发展序列；“停留、跨越、落地”等表述必须有同一过程中的真实时序证据。议程场域与法律人格、协作关系与法律隶属、资格开放与创设时实际参与要分别处理。
- 所有社会科学命题默认是暂时、概率性且有条件的；推断上限必须与证据一致。
- 任何稿件都要公开理论和分类选择，并写明可能推翻自己的证据。无法失败的主张不能作为承重贡献。
- 若 `results_validation.md` 等生成视图或正文与已确认问题、`method_execution.json`、
  `confirmed_contribution.md` 发生漂移，回到拥有事实的 research/design/execution 阶段修复，
  不能直接修改派生 Markdown 或在审计阶段用措辞掩盖。
