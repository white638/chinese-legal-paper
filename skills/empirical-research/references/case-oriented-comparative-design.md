# 案例导向比较研究设计

本专题把《案例导向研究的比较技艺：哲学基础与研究设计》中可迁移的内容转化为
cnki-paper 7.1.0 的设计与执行规则。教材只提供问题意识和路线知识；任何硬门还必须
得到独立方法来源支持，并且能够由身份、边界、能力、漂移、权限、登记状态或内容摘要
客观复核。

案例导向不是新的方法族，也不等同于“用了一个案例”。它是跨越 `case_study`、
`process_tracing`、`qca`、`comparative` 和 `congruence_analysis` 的设计剖面：
研究先界定案例总体、案例边界、选案逻辑、范围条件和材料角色，再决定个案内、跨案例
及其整合如何回答研究问题。历史研究是否采用这一剖面必须由研究者判断，不能只看
`historical` 标签。

## 一、四种因果与理论能力必须分开

适配器注册表分别登记四种能力：

| 能力 | 主要回答 | 典型路线 | 不能自动推出 |
|---|---|---|---|
| `causal_effect` | 干预或暴露相对比较基准造成多大差异 | 有明确识别条件的实验或定量路线 | 机制已经成立 |
| `causal_mechanism` | 结果通过哪些节点、时序和行动过程产生 | 过程追踪 | 平均效应、外推到未研究总体 |
| `causal_configuration` | 哪些条件组合构成必要、充分、合取或多路径关系 | QCA | 平均、边际或净效应 |
| `theory_evaluation` | 竞争理论的可区分预测与观察何者更相合 | 一致性分析及适用的案例/比较路线 | 单独证明效应或完整机制 |

普通案例研究可以描述、诠释、生成理论或评价理论，但不会因存在时间线或丰富材料就
自动获得机制能力。过程追踪以机制节点、预期痕迹、竞争机制、负面证据和证据诊断力
为中心。一致性分析以竞争理论、可区分预测、可观察含义和“预测—观察矩阵”为中心；
二者可以组合，但必须分别保留证据责任和推断上限。

## 二、设计身份与案例边界

`research_design.json.case_design` 在 v3 中始终存在：

- 案例导向路线使用 `applicability=active`；
- 明确不涉及案例导向的研究使用 `not-applicable`；
- 旧工作区中无法可靠推导的事实使用 `needs-review`，不能由关键词补成 PASS。

稳定身份链如下：

| 前缀 | 对象 | 最低边界 |
|---|---|---|
| `CUN-*` | 案例总体 | 纳入、排除、时间、空间、层级、分析单位 |
| `CAS-*` | 案例 | 总体归属、时间、层级、边界、选案策略、理论角色、选案时结果知情状态、材料角色 |
| `SCP-*` | 范围条件 | 条件陈述、状态、关联 Claim/Design/Evidence、对推断的影响 |
| `CMP-*` | 跨案例比较 | 至少两个 Case ID、比较逻辑、时间和层级对齐、共同/差异维度、威胁与上限 |
| `WCA-*` | 个案内分析 | Case/Design/Claim/Evidence 映射、分析模式、目的与推断上限 |

案例边界必须同时回答“什么是一个案例”“何时开始和结束”“位于什么层级”“哪些
行动者、组织、事件或空间被纳入”。仅写国家、组织或政策名称不足以形成可复核边界。
次国家比较必须把真正分析的省、市、县、机构或社区登记为 Case ID，并显式说明国家
与次国家层级怎样对齐；共同国别背景不会自动消除所有混杂。

## 三、理论目的决定选案角色

选案首先服务理论生成、修正、检验、相对评价、效应识别、机制解释、组态识别或类型
建构。`selection_strategy` 可登记受控比较、关键、典型、异常、最可能、最不可能、
差异性、类型学、次国家、理论性或结果差异等策略，但策略名称本身不构成识别。

`outcome_knowledge_at_selection` 必须说明选案时结果是未知、部分知情还是已知。已知
结果选案不是通用禁令；隐瞒知情状态是客观披露缺口，而其方法价值、偏差大小和可否
支持当前理论目的属于 REVIEW。任何选案都要写明：

1. 案例来自哪个可见总体；
2. 为什么这个案例对当前理论目的有信息；
3. 选案发生在材料收集、理论形成和结果观察的什么时点；
4. 哪些结论仍不能由该案例支持。

最相似、最不同、关键、典型或异常案例不会自动识别因果，也没有适用于所有研究的固定
案例数。

## 四、范围条件不是结尾的局限性套话

范围条件说明理论或主张在什么背景、时段、层级、制度和行动者条件下预期成立。设计时
以 `SCP-*` 连接 Claim ID、Design ID 与可用 Evidence ID；执行时记录维持、收窄、扩展
或修订，以及变化对推断上限的影响。

以下事实可硬检：范围条件身份不存在、引用未知 ID、设计与执行的 Scope ID 集合漂移、
修订未登记。以下问题必须由独立解释性研究运行评审并绑定理由与证据：范围条件是否有理论价值、
是否只是事后保护主张、观察是否充分、是否支持外推。单案例不会天然带来高内部效度，多个或跨国案例也不会
天然带来高外部效度。

## 五、个案内分析的分工

### 过程追踪

过程追踪路线必须在 `WCA-*` 中登记机制节点、节点时序、预期痕迹和竞争机制，并在
`method_execution.json` 中保存实际机制痕迹、支持或冲突结果、来源身份与负面证据。
缺少痕迹时不能把一般案例叙述包装成过程追踪。证据是否具有足够诊断力、来源是否真正
独立、断裂节点如何降低结论，保留为 REVIEW。

### 一致性分析

一致性分析登记至少两个可比较的竞争理论、各自预测和可观察含义；执行阶段形成
“理论预测—观察矩阵”，记录符合、不符合、不可观察和异常观察。它主要支持竞争理论的
相对评价。即使某理论与观察高度一致，也不能单凭一致性分析宣称平均效应或完整机制。

### 组合

两种个案内分析可先后或迭代使用。若同一材料先参与理论形成、后又被称为独立验证，
必须按同源材料循环使用阻塞；若材料只是被再次解释，应降低为非独立支持并写明上限。

## 六、跨案例比较与 QCA

跨案例设计至少登记两个不同 Case ID，并说明比较模式、时间对齐、层级对齐、共同维度、
差异维度、目标推断和威胁。受控比较、最相似和最不同设计只是组织比较的逻辑，不是
自动消除替代解释的识别器。比较可比性、典型性和次国家外推均属 REVIEW。

QCA 以集合关系和组态为答案对象。设计与执行应覆盖集合类型、条件与结果、校准依据、
真值表、矛盾组态、有限多样性、逻辑余项、解类型、稳健性和回到案例解释。执行结果
必须登记矛盾和负面发现；阈值选择保留为 REVIEW。不得把必要、充分、合取或多路径组态
改写成平均、边际或净效应，也不得声称 QCA 自动解决有限多样性。

## 七、整合顺序与材料角色

当项目同时包含跨案例和个案内分析时，`case_design.integration.sequence` 只能选择：

- `cross-case-first`：先用跨案例模式定位异质性、异常或有信息案例，再进行个案内分析；
- `within-case-first`：先由个案内材料形成或修正机制/理论，再设计跨案例检验；
- `iterative`：多轮交替，但每轮必须保留输入、输出、Case/Comparison/Within-case ID
  和范围修订；
- `single`：只有一种案例分析层次。

每次交接都要说明上一路线输出什么、下一路线接收什么、材料是否独立、冲突如何处理，
以及综合推断上限。方法并列、共享题目或共同出现在一章中不等于完成整合。

## 八、硬门与评审的边界

硬门只处理未知/重复 ID、案例边界缺失、跨案例不足两个案例、时间或层级未声明、
主张超出适配器能力、设计—执行漂移、未登记增删案例、同源材料伪装独立验证、遗漏
矛盾/负面结果、伦理权限缺项和内容哈希异常。

以下项目不得通用 PASS/FAIL：选案价值、典型性、代表性、范围条件质量、机制可信度、
比较可比性、次国家外推、理论预测区分度、QCA 阈值，以及任何固定案例数。输出中的
强结论必须服从路线能力与执行证据，不能由方法标签、教材示例或固定等级观替代。

覆盖清单和外部方法来源分别位于
`evals/case-oriented-v32/book_coverage.json` 与
`evals/case-oriented-v32/authoritative-method-sources.json`；二者只保存转化概括、
页码、来源身份和 PDF 摘要指纹，不复制教材正文。
